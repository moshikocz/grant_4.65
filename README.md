# סימולטור תנאי סף — הוראת מנכ"ל 4.65

**סטטוס:** בנוי. שלב 1 (תנאי סף) ושלב 2 (אמות מידה, מידע בלבד) פעילים. מותג:
בית לעסקים. מודולים עתידיים (אופן הגשה/בדיקה/תשלום/שו"ת) טרם נבנו — הארכיטקטורה
תומכת בהוספתם.

## מטרה

כלי (דף HTML/CSS/JS, לא דק מצגת) שבודק עבור עסק אם הוא עומד בתנאי הסף
לזכאות למענק לפי הוראת מנכ"ל 4.65. הכניסה לכלי מגויסת (gated) ע"י מודל
דיסקליימר/הסכמה על אחריות המשתמש, המוצג לפני חשיפת התוכן.

## מקור נתונים — חובה

תנאי הסף, הסכומים והקריטריונים נקראים מ:
`06_Knowledge_Vault/מיצוי-משאבים/מסלולי-מענקים/משרד-הכלכלה_4.65-האצה-עסקית-גבול-לבנון.md`
(ומ-`מאגר_מסלולים_מאוחד.md`). רשימת היישובים (תנאי סף 4.2) נמצאת בקובץ
ההחלטה המשותף `06_Knowledge_Vault/מיצוי-משאבים/החלטות-ממשלה/3841_יישובי-גבול-לבנון.md`
(רלוונטית גם למסלולים עתידיים אחרים על בסיס אותה החלטה — לא רק 4.65). תנאי הסף
של "סוג הגורם העסקי" (סעיף 2.2 להוראה) נגזר מהשדה החובה `סוגי_ישות_כשירים` בקובץ
המסלול, וזמין ב-`data.js` כ-`TRACK_DATA.notEligibleBusinessTypes` — `index.html`
קורא ממנו ולא מקודד את הרשימה בעצמו.
**אסור** לשכפל את הנתונים האלה בקוד הכלי (זה בדיוק מה שקרה בעבר עם רשימת סוגי
העסק שאינם כשירים, עד שתוקן — ר' `06_Knowledge_Vault/מיצוי-משאבים/AGENTS.md`).

## מבנה הכלי

- `index.html` — הסימולטור (HTML/CSS/JS טהור, מותג "בית לעסקים").
- `data.js` — **מיוצר אוטומטית** ע"י `sync_data.py`. אין לערוך ידנית.
- `sync_data.py` — קורא מהמאגר (כולל שני קבצי סיווג הלמ"ס תחת
  `06_Knowledge_Vault/נתונים נוספים/`) וכותב את `data.js`. להריץ מחדש אחרי כל
  שינוי בנתוני המסלול/יישובים/סיווגים במאגר: `python sync_data.py`.
- `brand/tokens.css`, `brand/Logo/לוגו הבית לעסקים משולב.jpg` — נכסי מותג
  שנשתלו (vendored) בריפו לצורך פריסה עצמאית (standalone deployment), ללא
  תלות בנתיב חיצוני למותג.
- `קבצים/נספח-2-טופס-אקסל-לחברה.xlsx`,
  `קבצים/נספח-3-טופס-אקסל-מובנה-לעוסק-מורשה.xlsx` — טפסי נספחים (אקסל)
  נלווים להגשה.

שלב 1 בודק 7 צעדים (6 תנאי הסף המקוריים + שאלת השקעות הון), בסדר: יישוב →
ענף כלכלי (כולל תת-בחירה לפי סדר, ותנאי מיוחד לסדרים C ו-S) → מחזור → ניהול
ושליטה בישראל → ללא חדלות פירעון → השקעות הון. שלב 2 מציג את אמות המידה
(סעיף 7) כמידע בלבד.

## הבא בתור

מודולים עתידיים אפשריים (לא נבנו): אופן ההגשה, אופן הבדיקה, תשלום, שאלות
ותשובות — כל מודול הוא `<section class="card">` נוסף ב-`index.html` (כמו
`step-threshold`/`step-scoring` הקיימים) עם לוגיקת הצגה/הסתרה משלו.
